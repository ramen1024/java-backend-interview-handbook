# 第 6 章 数据结构与算法：面试真正考的是复杂度意识

> 一句话定位：算法题只是表象，面试官真正在测的是你能不能在写代码之前估出代价、在写完代码之后说清边界。

## 一、本章考察重点概览

后端岗位的算法面试和校招的纯算法面试不是一回事。社招更常见的形式是"半小时聊项目 + 二十分钟手撕一道中等题 + 十分钟追问复杂度"。也就是说，手撕题的作用是**提供一个可以展开技术对话的载体**，而不是单纯比谁刷题多。面试官通过这一章主要看四件事：

1. **复杂度意识。** 拿到问题先问数据规模，再选结构。10 万条数据用 O(n²) 是事故，10 条数据用红黑树是过度设计。很多人能写出正确解，但说不出"为什么这里可以用 O(n log n) 而不用 O(n)"。
2. **边界与不变量。** 二分写不写得对，本质是能不能把"区间语义"讲清楚；快排写不写得对，本质是能不能守住"分区后 pivot 位置即最终位置"这个不变量。写代码时的边界处理习惯，直接映射到业务代码里的数组越界与空指针。
3. **对底层结构的直觉。** ArrayList 为什么在实践中常胜于 LinkedList、HashMap 为什么在链表长到 8 时转红黑树、数据库为什么选 B+ 树而不选红黑树——这些问题考的是"结构选择与硬件特性、IO 特性之间的关系"。
4. **能不能把算法迁移到工程。** LRU 就是缓存淘汰，单调栈就是"找下一个更大值"的滑动指标计算，并查集就是连通性判断（社交关系、网络分区、成环检测），布隆过滤器就是存在性预判。

## 四、题目详解

### Q1. 大 O 到底在说什么？均摊复杂度怎么算？（初级）

**一句话结论**：大 O 描述的是输入规模趋于无穷时运算量的**增长上界**，它刻意丢掉常数与低阶项，因此只能用来比较"量级"而不能用来比较"快慢"；均摊复杂度则是把偶发的高代价操作平摊到一串操作上，用总代价除以操作次数。

**先把话说白**：大 O 不是"运行时间"，而是"曲线形状"。O(n) 和 O(n²) 的差别不在于 n=10 时谁快——那时候常数因子说了算——而在于 n 翻倍时运算量翻几倍。均摊则像公司年会：一年办一次，一次花 30 万，摊到 12 个月就是每月 2.5 万，你不能因为 12 月花了 30 万就说"月度成本是 30 万"。

**底层原理**：

1. **定义与三个符号的区别。** 形式化地说，f(n) = O(g(n)) 表示存在常数 c 和 n₀，使得 n > n₀ 时 f(n) ≤ c·g(n)。所以大 O 是上界，Ω 是下界，Θ 是紧确界。面试里说"快排是 O(n log n)"严格讲是错的，应该说"平均 Θ(n log n)，最坏 O(n²)"，但口语中通常默认指平均情况。

2. **为什么可以丢掉常数。** 因为比较的是增长率。3n² 和 100n² 在 n 足够大时排序不变，而 n² 和 n log n 的排序会在某个 n 处反转。丢掉常数的代价是：n 较小时结论可能完全相反。插入排序是 O(n²)，但对 8 个元素的小数组，它比归并快得多——这正是 JDK 在数组长度小于阈值（JDK 8 的双轴快排里是 47）时切换插入排序的原因。

3. **最好 / 最坏 / 平均必须分开说。** 快排最坏 O(n²)（每次划分极不均衡）、平均 O(n log n)、最好 O(n log n)；插入排序最坏 O(n²)、最好 O(n)（已有序）。工程上关心的是**最坏情况是否能接受**，因为最坏情况往往由攻击者或异常数据触发，而不是随机出现。HashMap 的树化就是为了把"最坏 O(n)"压到"最坏 O(log n)"。

4. **均摊分析的三种方法。** 以动态数组扩容为例（ArrayList 每次容量不足时扩到 1.5 倍，`Vector` 是 2 倍）：
   - 聚合法：连续 n 次 add，扩容发生在 1、2、4、8…，总拷贝次数为 1+2+4+…+n < 2n，总代价 O(n)，均摊到每次是 O(1)。
   - 记账法：每次 add 存 3 块钱，1 块付自己的写入，2 块预存给未来搬移，永远不会透支。
   - 势能法：定义势能为"已用容量与容量之差的倍数"，每次操作的均摊代价 = 实际代价 + 势能变化，求和后势能非负，故总代价有上界。

5. **均摊不等于平均。** 平均复杂度是对**输入分布**求期望（快排的平均情况假设 pivot 随机），均摊复杂度是对**操作序列**求平均，不涉及概率。这是最容易混的一点：`ArrayList.add` 的均摊 O(1) 是无条件成立的，不依赖任何概率假设；而"快排平均 O(n log n)"依赖输入随机。

6. **空间换时间的判断方法。** 三步问：① 时间瓶颈在哪，是否可被缓存；② 额外空间的量级是否可接受（内存是否是瓶颈资源）；③ 是否有更省空间的等价结构。比如"判断 URL 是否访问过"，用 HashSet 存全量字符串是 O(n) 空间，用布隆过滤器是固定几位每元素但允许误判，用 Bitmap 则要求数据能映射到有限整数域。三者不是"哪个更好"，而是"哪个约束更紧"。

**代码 / 图示**：

```java
// 用一段可运行的代码验证均摊：统计 n 次 add 的总搬移次数
public static void main(String[] args) {
    int n = 1 << 20;
    int capacity = 1, size = 0;
    long moves = 0;
    for (int i = 0; i < n; i++) {
        if (size == capacity) {      // 触发扩容
            moves += size;           // 搬移已有元素
            capacity <<= 1;          // 容量翻倍
        }
        size++;
    }
    System.out.println("总搬移 " + moves + "，均摊 " + (double) moves / n); // 约 1.0
}
```

**易混对比**：

| 概念 | 描述对象 | 是否依赖概率 | 典型例子 |
| --- | --- | --- | --- |
| 最坏复杂度 | 最不利输入 | 否 | 快排 O(n²) |
| 平均复杂度 | 输入分布下的期望 | 是 | 快排平均 O(n log n) |
| 均摊复杂度 | 一段操作序列的平均 | 否 | `ArrayList.add` 均摊 O(1) |

**面试追问**：
- 追问：为什么 ArrayList 扩容是 1.5 倍而不是 2 倍？→ 答题要点：1.5 倍在老容量被回收后，新容量可以复用前面释放的内存块（2 倍时总和恰好差 1 个旧容量，永远无法复用），代价是扩容更频繁，是空间利用率与拷贝次数的折中。
- 追问：O(1) 的操作一定比 O(n) 快吗？→ 答题要点：不一定，要看常数与 n 的实际范围；哈希表 O(1) 的常数包含 hash 计算与一次随机内存访问，小 n 时不如顺序扫描。
- 追问：递归的空间复杂度怎么算？→ 答题要点：算递归栈深度，快排平均 O(log n)、最坏 O(n)；尾递归可被部分语言优化，JVM 不优化。

### Q2. 数组和链表怎么选？为什么 ArrayList 在实践中常胜？（初级）

**一句话结论**：数组把元素放在连续内存里，靠下标一次寻址即可命中，且能吃到 CPU 缓存行与硬件预取的红利；链表靠指针跳转，逻辑上插入删除是 O(1)，但定位仍是 O(n)，且每个节点都是独立对象、内存分散。所以除了"已知节点位置的高频中间插入删除"或"需要稳定引用的场景"，实践中 ArrayList 几乎总是更优。

**先把话说白**：数组像一排连号的座位，你说"第 5 个"，一步就走到；链表像一张写着"下一个在哪"的纸条接力，要去第 5 个必须一站一站问。表面看链表插入只要改两根指针，但前提是你**已经站在那个位置**——而走到那个位置本身就要 O(n)，且每一步都可能是一次缓存未命中。

**底层原理**：

1. **内存布局决定寻址代价。** 数组的地址是 `base + i * size`，一条乘加指令；链表要先读 `next` 指针再解引用，是**串行依赖**的访存链，无法并行，也无法预取。这是"指针追逐（pointer chasing）"问题。

2. **CPU 缓存局部性。** 一次内存访问会把整个缓存行（cache line，x86 通常 64 字节）加载进 L1/L2。数组遍历时，加载 1 个 int 顺带带进 15 个，后续访问全部命中；链表节点由 `new` 分散在堆上，几乎每次 `next` 都是一次 L3 甚至主存访问。二者在顺序遍历上的实测差距常在一个数量级以上，且随数据量增大而扩大。

3. **插入删除的真实代价。** `ArrayList.add(index, e)` 要 `System.arraycopy` 搬移后面所有元素，复杂度 O(n)，但搬移是连续内存的 `memmove`，带宽极高（每秒数 GB 级）；`LinkedList.add(index, e)` 先要 `node(index)` 走 O(n) 步指针，再改指针。所以"链表插入 O(1)"只在**持有节点引用**时成立，比如迭代器遍历中删除当前节点。

4. **对象开销。** `LinkedList.Node` 在 64 位 HotSpot 下开启压缩指针时约 24 字节对象头 + 3 个引用（item、prev、next）= 约 40 字节，而它承载的数据可能只是一个 4 字节 int。ArrayList 只存引用本身（4 字节压缩指针），外加扩容时的冗余容量。同样的数据量，LinkedList 的内存占用常是 ArrayList 的 3~5 倍。

5. **什么情况下链表真的更优。** ① 需要在遍历中频繁删除当前元素（用 `Iterator.remove()`，O(1)）；② 元素本身很大且不能移动（移动成本高于指针改写）；③ 需要稳定的节点引用作为句柄（如 LRU 的双向链表、`LinkedHashMap` 的访问序）；④ 内存碎片化严重、无法分配大块连续空间。LRU 用双向链表正是因为要"O(1) 摘除任意已知节点"。

**代码 / 图示**：

```java
// 对比：同样删除所有偶数，ArrayList 用迭代器是 O(n)，LinkedList 也是 O(n)
// 但 ArrayList 的 remove 每次搬移，LinkedList 只改指针——数据量大时 ArrayList 反而更快
List<Integer> list = new ArrayList<>();
for (int i = 0; i < 1_000_000; i++) list.add(i);

long s = System.nanoTime();
list.removeIf(x -> (x & 1) == 0);   // 内部一次遍历 + 一次批量搬移
System.out.println((System.nanoTime() - s) / 1_000_000 + "ms");
```

| 维度 | ArrayList | LinkedList |
| --- | --- | --- |
| 底层结构 | 动态数组 | 双向链表 |
| 随机访问 | O(1) | O(n) |
| 头部插入 | O(n) | O(1) |
| 中间插入（按下标） | O(n) 搬移，常数小 | O(n) 定位 + O(1) 改指针，常数大 |
| 内存开销 | 紧凑，有冗余容量 | 每节点约 40 字节，缓存不友好 |
| 迭代器删除 | O(n) 一次搬移 | O(1) |

**面试追问**：
- 追问：为什么 `LinkedList` 也实现了 `Deque`，但做队列不如 `ArrayDeque`？→ 答题要点：`ArrayDeque` 是环形数组，无需为每个元素分配节点，也没有指针追逐，头尾操作都是 O(1) 且缓存友好。
- 追问：ArrayList 扩容为什么用 `Arrays.copyOf` 而不是逐个复制？→ 答题要点：`System.arraycopy` 是 intrinsic，JIT 会替换为向量化指令或 `memmove`，比 Java 循环快一个量级。
- 追问：数组下标为什么从 0 开始？→ 答题要点：`base + i * size` 直接用 i，若从 1 开始每次要多一次减法；这是 Dijkstra 给出的解释，属于实现便利而非数学必然。

### Q3. 如何用两个栈实现队列？（初级）

**一句话结论**：用 `in` 栈接收入队，用 `out` 栈提供出队；只有当 `out` 为空时，才把 `in` 中的元素**全部**倒入 `out`。单次 `pop` 最坏 O(n)，但每个元素最多被搬运两次，均摊 O(1)。

**先把话说白**：栈是"后进先出"，队列是"先进先出"。把一摞盘子从 A 柱逐个搬到 B 柱，顺序就反过来了——这就是两次逆序等于正序。关键细节是"必须一次倒完"，如果倒一半就停，顺序会乱。

**底层原理**：

1. **核心不变量。** `out` 栈的栈顶永远是队列头；`out` 非空时不允许从 `in` 倒入，否则新倒入的元素会压在老元素上面，破坏顺序。

2. **均摊分析。** 每个元素的一生：入 `in`（1 次 push）→ 可能被倒入 `out`（1 次 pop + 1 次 push）→ 从 `out` 弹出（1 次 pop）。总操作次数与元素数成正比，均摊 O(1)。

3. **边界条件。** 两个栈都空时 `pop`/`peek` 要抛异常或返回特定值；`out` 非空但 `in` 也有元素时，必须继续从 `out` 取。

4. **反向问题：两个队列实现栈。** 每次 push 时把新元素放入空队列，再把另一个队列的元素全部搬过来，保证队头是栈顶。push O(n)、pop O(1)。也可以用"一个队列 + 循环搬移 size-1 次"实现，push O(n)、pop 均摊 O(1)。

```java
class MyQueue {
    private final Deque<Integer> in = new ArrayDeque<>();
    private final Deque<Integer> out = new ArrayDeque<>();

    public void push(int x) { in.push(x); }

    public int pop() {
        move();                       // 保证 out 非空
        return out.pop();
    }

    public int peek() {
        move();
        return out.peek();
    }

    public boolean empty() { return in.isEmpty() && out.isEmpty(); }

    private void move() {
        if (out.isEmpty()) {          // 必须整批搬，且只在 out 空时搬
            while (!in.isEmpty()) out.push(in.pop());
        }
    }
}
```

**易混对比**：

| 目标 | 结构组合 | push | pop | 关键点 |
| --- | --- | --- | --- | --- |
| 两栈实现队列 | in + out | O(1) | 均摊 O(1)，最坏 O(n) | out 空时整批倒 |
| 两队列实现栈 | q1 + q2 | O(n) | O(1) | 每次把老元素搬到新元素后面 |
| 单队列实现栈 | 一个队列 | O(n) | O(1) | push 后把前 size-1 个轮转 |

**面试追问**：
- 追问：为什么不能"倒一半"？→ 答题要点：倒入是逆序操作，只倒一部分会让 `out` 中混入顺序错误的元素，队头不再是真正的队头。
- 追问：多线程下这个结构安全吗？→ 答题要点：不安全，`move()` 的判空与倒栈不是原子操作，需要加锁或换用 `BlockingQueue`。
- 追问：如果要求 pop 严格 O(1) 怎么办？→ 答题要点：只能换结构，用环形数组 `ArrayDeque`，头尾指针各管一端。

### Q4. 单调栈解决什么问题？下一个更大元素怎么写？（中级）

**一句话结论**：单调栈用于求"每个元素左侧/右侧第一个比它大（或小）的元素"，核心是**维护一个单调的候选栈**：当新元素破坏单调性时，弹出栈顶并结算栈顶的答案。每个元素最多入栈一次、出栈一次，时间 O(n)、空间 O(n)。

**先把话说白**：想象一群人排队看演唱会，后面来了个更高的人，前面所有比他矮的人就再也看不到舞台了——他们此刻就"被结算"了。栈里留下的永远是"还没找到更大值"的递减序列，所以栈是单调的。

**底层原理**：

1. **为什么暴力是 O(n²)。** 对每个 i 向右扫描直到找到更大值，最坏（递减数组）每次扫到底。

2. **单调栈的机制。** 求"下一个更大元素"时维护**从栈底到栈顶递减**的栈（存下标）。遍历到 i 时，若 `nums[i] > nums[栈顶]`，说明栈顶元素的答案就是 i，弹出并记录；重复直到栈顶 ≥ nums[i]，再把 i 入栈。遍历结束后栈中剩余元素没有更大值，答案为 -1。

3. **为什么是 O(n)。** 每个下标恰好入栈一次、出栈一次，内层 while 的总执行次数不超过 n，是"均摊 O(1)"的典型。

4. **单调性的方向口诀。** 求"下一个更大"→ 栈内递减，遇到大的就弹；求"下一个更小"→ 栈内递增，遇到小的就弹。想不清时就从"栈顶什么时候该结算"倒推。

5. **循环数组。** 把数组长度翻倍遍历（`i % n`），或者遍历两遍，即可处理环形。接雨水、柱状图最大矩形、每日温度都是同一套。

```java
// 下一个更大元素 I：返回每个位置右侧第一个更大值的下标，没有则 -1
public static int[] nextGreater(int[] nums) {
    int n = nums.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);
    Deque<Integer> stack = new ArrayDeque<>();   // 存下标，栈内对应值递减
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && nums[i] > nums[stack.peek()]) {
            res[stack.pop()] = i;                // 结算：栈顶的答案就是 i
        }
        stack.push(i);
    }
    return res;                                  // 栈中剩余的保持 -1
}
```

**易混对比**：

| 结构 | 存什么 | 单调方向 | 典型题 |
| --- | --- | --- | --- |
| 单调栈 | 下标 | 递减（求更大）/ 递增（求更小） | 每日温度、柱状图最大矩形、接雨水 |
| 单调队列 | 下标 | 递减（求窗口最大） | 滑动窗口最大值 |
| 优先队列 | 元素 | 堆序 | TopK、合并 K 个链表 |

**面试追问**：
- 追问：为什么栈里存下标而不是值？→ 答题要点：需要计算距离（每日温度）或定位结果数组，值无法反查位置；有重复值时下标也唯一。
- 追问：接雨水怎么用单调栈做？→ 答题要点：栈内递减存下标，遇到更高的柱子时弹出低洼，按"左右边界高度取小减底"计算横向水槽面积。
- 追问：单调栈和单调队列的区别？→ 答题要点：栈只在一端进出，处理"到某个元素为止的历史"；队列两端都可出，能淘汰过期元素，适合滑动窗口。

### Q5. 滑动窗口最大值怎么做到 O(n)？（中级）

**一句话结论**：用双端队列维护**窗口内元素的下标**，队列中的值从队头到队尾严格递减，队头即当前窗口最大值。新元素入队前从队尾弹出所有比它小的元素（它们不可能再成为最大值），同时从队头弹出已滑出窗口的下标。每个下标进出各一次，O(n)。

**先把话说白**：窗口里如果有个"又大又新"的元素，那么所有"又小又老"的元素就永远没机会当最大值了——既比不过，也会先过期。所以可以直接把它们从候选队列里删掉。队列里剩下的是一条"又大又新"的单调序列。

**底层原理**：

1. **淘汰规则的两个维度。** ① 值维度：新元素比队尾大，队尾永远不可能在后续窗口成为最大值（新元素比它大且比它活得久），弹出；② 时间维度：队头下标 ≤ i - k，说明已不在窗口内，弹出。

2. **为什么队头就是最大值。** 队列单调递减，队头最大；且队头是"当前窗口内最大的、且未过期的"元素。

3. **复杂度。** 每个下标最多入队一次、出队一次，总操作 O(n)。暴力法是 O(nk)。

4. **与堆的对比。** 用大顶堆需要 O(n log n)，且要处理"堆顶已过期"的惰性删除。单调队列的优势是把"过期"和"非最优"这两类元素一次性清理干净。

```java
public static int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();      // 存下标，值递减
    for (int i = 0; i < n; i++) {
        // 1. 队头过期（下标 <= i-k）
        if (!dq.isEmpty() && dq.peekFirst() <= i - k) dq.pollFirst();
        // 2. 队尾比当前小的都不可能再当最大值
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[i]) dq.pollLast();
        dq.offerLast(i);
        // 3. 窗口形成后记录答案
        if (i >= k - 1) res[i - k + 1] = nums[dq.peekFirst()];
    }
    return res;
}
```

**易混对比**：

| 方案 | 时间复杂度 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 暴力扫描 | O(nk) | O(1) | k 大时不可用 |
| 大顶堆 | O(n log n) | O(k) | 需惰性删除过期堆顶 |
| 单调队列 | O(n) | O(k) | 逻辑细节多，易漏过期判断 |

**面试追问**：
- 追问：为什么用 `<=` 而不是 `<` 弹队尾？→ 答题要点：相等时也应弹出旧元素，保留新元素（活得更久），否则旧元素过期后还要多一次清理，结果不受影响但效率略差。
- 追问：如果要求返回窗口内的中位数呢？→ 答题要点：单调队列不适用，需要两个堆（对顶堆）或有序容器，复杂度 O(n log k)。
- 追问：队列里最多存多少个元素？→ 答题要点：最多 k 个，所以空间 O(k)。

### Q6. 哈希表怎么解决冲突？为什么 Java 用链地址 + 红黑树？（中级）

**一句话结论**：哈希冲突有两类解法——链地址法（每个桶挂一条链）和开放寻址法（按探测序列找下一个空位）。Java 的 `HashMap` 选链地址，因为它对高负载因子容忍度高、删除不需要墓碑、且 key 是对象引用不便做紧凑存储；JDK 8 起在链表长度 ≥ 8 且数组长度 ≥ 64 时把链表转成红黑树，把最坏查找从 O(n) 压到 O(log n)，主要用于防御哈希碰撞攻击。

**先把话说白**：哈希表就是"按身份证号分抽屉"，理想情况一人一格。但抽屉数量有限，难免有人分到同一格。链地址法是"同一格里挂一串"，开放寻址法是"这格有人了，就按规则看下一格"。前者简单粗暴但要多存指针，后者省内存但对负载因子极敏感。

**底层原理**：

1. **哈希到桶位。** `HashMap` 用 `(n - 1) & hash` 定位桶，n 是 2 的幂，所以位运算等价于取模但更快。`hash` 不是 `hashCode()` 原值，而是 `h ^ (h >>> 16)`——把高 16 位异或到低 16 位，因为桶数通常很小，只用低位会导致高位信息浪费、冲突集中。

2. **链地址法（Separate Chaining）。** 每个桶存链表头。插入时头插（JDK 7）或尾插（JDK 8，为避免并发扩容成环）。负载因子默认 0.75，元素数超过 `capacity * 0.75` 就扩容为 2 倍并 rehash。删除只需摘链，O(1) 定位 + O(链长) 查找。

3. **开放寻址法（Open Addressing）。** 冲突时按 `(h + i) % n`（线性探测）、`(h + i²) % n`（二次探测）或双重哈希找下一个空位。优点是数据全在数组里、缓存友好、无需指针；缺点是删除必须用墓碑（tombstone）标记，否则会截断探测链；负载因子必须控制在 0.5~0.7 以下，接近满时探测长度爆炸。Python 的 dict、Go 的 map（部分实现）、Rust 的 HashMap（SwissTable）走这条路。

4. **为什么 Java 不用开放寻址。** ① Java 的 key 是对象引用，开放寻址要求元素紧凑存放，而引用本身可以，但 `Node` 还要存 hash 与 next，链地址更自然；② `HashMap` 允许 null key、允许任意对象，开放寻址对"删除频繁"的场景需要墓碑，长期运行会退化；③ 链地址在高负载因子下只是变慢，不会像开放寻址那样直接失败。

5. **为什么阈值是 8 和 64。** 在理想哈希（泊松分布）下，桶内链表长度达到 8 的概率约为 0.00000006，即千万分之一。也就是说正常情况下几乎不会树化，树化只是兜底。数组长度 < 64 时优先扩容而不是树化，因为小数组扩容成本更低、效果更好。

6. **树化与退化。** 树化条件：链表长度 ≥ 8 **且** 数组长度 ≥ 64。退化条件：扩容后树节点数 ≤ 6 转回链表。阈值不对称（8 与 6）是为了避免在 7 附近反复转换（抖动）。

7. **扩容的代价。** 扩容要重新分配数组并把所有节点重新分布，O(n)。JDK 8 利用"容量是 2 的幂"这个性质，把每个节点分成"低位链"和"高位链"两条，无需重新计算 hash，只需判断 `hash & oldCap` 是否为 0。这是工程上的经典优化。

**代码 / 图示**：

```java
// JDK 8 HashMap 的 hash 扰动与定位
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
// 定位：tab[(n - 1) & hash]，n 为 2 的幂
```

**易混对比**：

| 维度 | 链地址法 | 开放寻址法 |
| --- | --- | --- |
| 存储 | 数组 + 链表/树 | 纯数组 |
| 负载因子容忍度 | 高（可 > 0.75） | 低（通常 ≤ 0.7） |
| 删除 | 直接摘链 | 需要墓碑标记 |
| 缓存友好性 | 差（节点分散） | 好（连续内存） |
| 典型实现 | Java HashMap、Redis dict | Python dict、Rust SwissTable |

**面试追问**：
- 追问：为什么 `HashMap` 容量必须是 2 的幂？→ 答题要点：`(n-1) & hash` 等价于取模但快得多，且扩容时可用 `hash & oldCap` 判断高低位，避免重算 hash。
- 追问：负载因子为什么是 0.75？→ 答题要点：空间与查询的折中。太低浪费空间，太高冲突率上升；0.75 在泊松分布下能让链长超过 8 的概率极低。
- 追问：并发下 `HashMap` 会怎样？→ 答题要点：JDK 7 头插法在并发扩容时可能形成环形链表导致 CPU 100%；JDK 8 改尾插避免了成环，但仍会丢数据，并发场景必须用 `ConcurrentHashMap`。
- 追问：为什么 String 适合做 key？→ 答题要点：不可变（hash 可缓存）、`hashCode` 分布均匀、实现了 `equals`。

### Q7. 二叉树遍历的递归、迭代、Morris 怎么写？（中级）

**一句话结论**：前中后序的递归写法只是"访问根"的位置不同；迭代写法用显式栈模拟递归栈，其中**中序**的模板是"一路向左压栈，弹出即访问，再转向右子树"；Morris 遍历利用叶子节点的空右指针建立临时线索，把空间降到 O(1)。

**先把话说白**：递归是"编译器帮你维护栈"，迭代是"你自己维护栈"。Morris 更巧：它发现中序遍历时，一个节点的前驱（左子树最右节点）的右指针一定是空的，那就临时把它指回自己，走完左子树后顺着这根"回头路"回来，用完再拆掉——相当于在树上临时画了几条便签，不占额外空间。

**底层原理**：

1. **三种递归序的本质。** 每个节点在递归过程中会被"经过"三次（进入、左子树返回、右子树返回）。前序在第 1 次经过时访问，中序在第 2 次，后序在第 3 次。理解了这一点，三种写法就不需要背。

2. **中序迭代的模板。** `cur = root`；当 `cur != null` 或栈非空：一路 `push(cur)` 并 `cur = cur.left`；然后 `cur = stack.pop()`，访问，`cur = cur.right`。这个模板只需微调就能得到前序（入栈时访问）和"根右左"的反序后序。

3. **后序迭代的两种写法。** ① 按"根 → 右 → 左"遍历再反转结果，等价于后序；② 记录 `lastVisited`，栈顶的右子树为空或已访问时才弹出。

4. **Morris 的线索化过程。** 对当前节点 `cur`：若 `cur.left == null`，访问 `cur`，`cur = cur.right`；否则找左子树的**最右节点** `pre`：若 `pre.right == null`，令 `pre.right = cur`（建线索），`cur = cur.left`；若 `pre.right == cur`，说明左子树已遍历完，令 `pre.right = null`（拆线索），访问 `cur`，`cur = cur.right`。

5. **Morris 的复杂度。** 时间 O(n)：每条边最多被走 3 次（建线索、遍历、拆线索），常数因子约 2~3 倍于递归；空间 O(1)。代价是**遍历过程中会临时修改树结构**，多线程下不安全，且代码可读性差，工程中很少用，属于面试展示深度的内容。

6. **层序遍历。** 用队列，每次先记录 `size = queue.size()`，一次性处理完一整层，这样才能按层输出或求层宽。

```java
// 中序迭代：最通用、最不容易写错的模板
public List<Integer> inorder(TreeNode root) {
    List<Integer> res = new ArrayList<>();
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stack.isEmpty()) {
        while (cur != null) {          // 一路向左，压栈
            stack.push(cur);
            cur = cur.left;
        }
        cur = stack.pop();             // 弹出即访问（中序位置）
        res.add(cur.val);
        cur = cur.right;               // 转向右子树
    }
    return res;
}

// Morris 中序：空间 O(1)
public List<Integer> morrisInorder(TreeNode root) {
    List<Integer> res = new ArrayList<>();
    TreeNode cur = root;
    while (cur != null) {
        if (cur.left == null) {
            res.add(cur.val);
            cur = cur.right;
        } else {
            TreeNode pre = cur.left;
            while (pre.right != null && pre.right != cur) pre = pre.right; // 找前驱
            if (pre.right == null) {         // 第一次到达：建线索
                pre.right = cur;
                cur = cur.left;
            } else {                          // 第二次到达：拆线索并访问
                pre.right = null;
                res.add(cur.val);
                cur = cur.right;
            }
        }
    }
    return res;
}
```

**易混对比**：

| 遍历方式 | 访问根的位置 | 迭代关键点 | 空间 |
| --- | --- | --- | --- |
| 前序 | 入栈时 | 弹出即访问，先压右再压左 | O(h) |
| 中序 | 弹出时 | 一路向左压栈，弹出访问后转右 | O(h) |
| 后序 | 左右都完成后 | 反序法或记录 lastVisited | O(h) |
| 层序 | 按层 | 队列 + 每层固定 size | O(w) |
| Morris 中序 | 第二次到达时 | 借前驱空右指针做线索 | O(1) |

**面试追问**：
- 追问：递归遍历的空间复杂度是 O(log n) 还是 O(n)？→ 答题要点：取决于树高。平衡树 O(log n)，退化成链表时 O(n)，递归栈溢出就发生在这种情况。
- 追问：Morris 能用于后序吗？→ 答题要点：可以，但需要额外处理"逆序输出右边界路径"，实现复杂度显著上升，面试一般不要求。
- 追问：如何判断一棵树是否对称 / 平衡？→ 答题要点：对称用双指针同时向内侧递归；平衡用后序返回高度，一旦某子树不平衡就返回 -1 剪枝，避免 O(n²)。

### Q8. 由前序和中序能唯一还原二叉树吗？（中级）

**一句话结论**：前序 + 中序可以唯一还原，后序 + 中序也可以；但前序 + 后序**不能**唯一确定（无法区分只有一个孩子时它是左还是右）。还原的核心是"前序首元素定根，中序按根分成左右两段，递归处理"，用哈希表把定位根的 O(n) 降到 O(1)，总复杂度 O(n)。

**先把话说白**：前序是"根在最前面"，中序是"根在中间，左边全是左子树，右边全是右子树"。所以拿到前序第一个就知道根是谁，再去中序里找它的位置，左右两边的长度就确定了——长度确定，前序里对应的片段也就切出来了。这是个纯切分问题。

**底层原理**：

1. **切分规则。** 前序 `[preL, preR]`，中序 `[inL, inR]`。根是 `pre[preL]`，在中序中的位置是 `k`，则左子树大小 `leftSize = k - inL`。左子树前序区间 `[preL+1, preL+leftSize]`，右子树 `[preL+leftSize+1, preR]`。

2. **为什么前序 + 后序不行。** 前序 `[根, 左..., 右...]`，后序 `[左..., 右..., 根]`。当某节点只有一个孩子时，前序中该孩子紧跟在根后，后序中该孩子紧挨在根前，两种情况下都成立，无法判断是左还是右。例如前序 `[1,2]`、后序 `[2,1]`，2 可以是 1 的左孩子也可以是右孩子。中序能提供"左右分界"，所以必须有中序。

3. **重复元素的问题。** 若树中存在重复值，中序定位根会有歧义，无法唯一还原。所以这类题默认值唯一，或者需要额外的位置信息。

4. **迭代写法（进阶）。** 用栈模拟：前序依次入栈，若栈顶不等于当前中序元素则继续压左孩子；相等则弹出并转向右子树。代码更绕但同样是 O(n)。

```java
// 前序 + 中序还原，用 Map 把定位降到 O(1)
private Map<Integer, Integer> index = new HashMap<>();
private int[] pre;

public TreeNode buildTree(int[] preorder, int[] inorder) {
    this.pre = preorder;
    for (int i = 0; i < inorder.length; i++) index.put(inorder[i], i);
    return build(0, preorder.length - 1, 0, inorder.length - 1);
}

private TreeNode build(int preL, int preR, int inL, int inR) {
    if (preL > preR) return null;                 // 空区间
    int rootVal = pre[preL];
    int k = index.get(rootVal);                   // 根在中序中的位置
    int leftSize = k - inL;
    TreeNode root = new TreeNode(rootVal);
    root.left  = build(preL + 1, preL + leftSize, inL, k - 1);
    root.right = build(preL + leftSize + 1, preR, k + 1, inR);
    return root;
}
```

**易混对比**：

| 组合 | 能否唯一还原 | 原因 |
| --- | --- | --- |
| 前序 + 中序 | 能 | 前序定根，中序分左右 |
| 后序 + 中序 | 能 | 后序末元素定根，中序分左右 |
| 层序 + 中序 | 能 | 层序首元素定根 |
| 前序 + 后序 | 不能 | 单孩子时无法区分左右 |
| 前序 + 后序（满二叉树） | 能 | 满二叉树每个节点要么 0 个要么 2 个孩子 |

**面试追问**：
- 追问：还原一棵 BST 需要几个序列？→ 答题要点：只需前序或后序之一，因为 BST 的中序就是升序，可由排序得到。
- 追问：如果树很大，递归会不会栈溢出？→ 答题要点：会，退化树深度等于节点数，需要改成显式栈迭代，或增大 `-Xss`。
- 追问：如何序列化和反序列化一棵二叉树？→ 答题要点：前序遍历 + 空节点占位符（如 `#`），反序列化按同样顺序消费；LeetCode 的层序格式也是同理。

### Q9. BST、AVL、红黑树、B+ 树的演进逻辑是什么？为什么数据库选 B+ 树？（高级）

**一句话结论**：这条演进线是"用平衡性换查询稳定性"的过程。BST 在有序插入时退化成链表；AVL 用严格平衡（左右子树高差 ≤ 1）保证 O(log n) 但旋转频繁；红黑树放宽到"最长路径不超过最短路径的 2 倍"，用颜色约束把插入/删除的旋转次数压到常数级；B/B+ 树把二叉变多叉，专为**磁盘页**设计——一次 IO 读一页，多叉能把树高压到 3~4 层，这是红黑树做不到的。

**先把话说白**：BST 像一本按字母排好的字典，理想情况翻几次就找到；但如果每次新词都插在最后，字典就变成一条长龙，只能一页页翻。AVL 是"稍微歪一点就立刻扶正"，很整齐但整理成本高；红黑树是"允许歪一点，只要不太歪"，省事。而数据库面对的不是内存而是磁盘，一次读盘要 10 毫秒，与其在二叉树上多跳几层、每层都读一次盘，不如一层里塞几百个 key，三层就覆盖上亿行——这就是 B+ 树的全部动机。

**底层原理**：

1. **BST 的退化。** 插入 1,2,3,4,5 会得到一条右斜链，查找 O(n)。BST 的查找效率完全依赖"树的形状"，而形状由插入顺序决定，这是它不能直接用于生产的原因。

2. **AVL 的严格平衡。** 每个节点维护平衡因子（左高 - 右高），取值只能是 -1、0、1。失衡分四种：LL、RR、LR、RL，分别用单旋或双旋修复。查询最坏 O(log n)，但插入/删除可能沿路径一路旋转到根，旋转次数 O(log n)，写多的场景代价高。

3. **红黑树的近似平衡。** 五条性质：节点非红即黑；根为黑；叶子（NIL）为黑；红节点的子节点必为黑（不能红红相连）；从任一节点到其所有叶子的路径上黑节点数相同（黑高一致）。由这些性质可推出：最长路径 ≤ 2 × 最短路径，因此树高 ≤ 2log₂(n+1)，查找仍是 O(log n)。代价是插入最多 2 次旋转、删除最多 3 次旋转，**旋转次数是常数**，这就是它比 AVL 更适合写多场景的原因。Java 的 `TreeMap`、`HashMap` 的桶、Linux 的 CFS 调度器、epoll 的内核实现都用红黑树。

4. **磁盘 IO 的定量直觉。** 机械盘一次随机读约 5~10 ms，SSD 约 0.05~0.2 ms。假设一次 IO 读一页 16 KB（InnoDB 默认页大小）。红黑树每个节点只存一个 key，树高约 log₂(n)：1 亿行约 27 层，最坏 27 次 IO，按 SSD 算约 1.5~5 ms，按机械盘算是几百毫秒——完全不可接受。

5. **B+ 树的算术。** InnoDB 的非叶子节点存"键值 + 6 字节页号"。假设主键是 bigint（8 字节），一条索引项约 8 + 6 = 14 字节，加上页内偏移等开销按 16 字节算。一页 16 KB 可存约 1000 个指针。三层 B+ 树：根 1000 个指针 → 第二层 1000 × 1000 = 100 万 → 叶子层每页假设存 100 行，总共约 1 亿行。也就是说**上亿行数据只需 3 次 IO**，且根节点和第二层常驻内存（buffer pool），实际只需 1 次 IO。

6. **为什么是 B+ 而不是 B 树。** ① B 树的非叶子节点也存数据，同样一页能放的指针更少，树更高；② B+ 树数据全在叶子，叶子之间用双向链表连接，范围查询（`WHERE id BETWEEN 1 AND 100`）只需定位起点再顺序扫描链表，B 树则要做中序回溯；③ B+ 树每次查询都必须走到叶子，路径长度稳定，IO 次数可预测；④ 全表扫描时 B+ 树只需遍历叶子链表，B 树要遍历整棵树。

7. **内存结构为什么不用 B+ 树。** 内存没有"页 IO"的概念，随机访问代价与顺序访问差距远小于磁盘（差一个数量级左右，而磁盘差几个数量级）。B+ 树节点大、页内二分查找、节点分裂合并的逻辑复杂，在内存里收益不足以抵消复杂度。红黑树实现简单、旋转常数级、单点查找稳定 O(log n)，是内存有序结构的默认选择。

**易混对比**：

| 结构 | 平衡策略 | 树高 | 插入旋转次数 | 适用介质 | 典型实现 |
| --- | --- | --- | --- | --- | --- |
| BST | 无 | 最坏 O(n) | 0 | 不适合生产 | 教学 |
| AVL | 严格（高差 ≤ 1） | ≤ 1.44 log n | O(log n) | 读多写少 | 早期索引 |
| 红黑树 | 近似（最长 ≤ 2×最短） | ≤ 2 log(n+1) | O(1)（≤2/≤3） | 内存 | TreeMap、epoll |
| B 树 | 多叉 + 节点内有序 | 约 logₘ n | 分裂/合并 | 磁盘 | MongoDB 早期索引 |
| B+ 树 | 多叉 + 数据全在叶子 | 约 logₘ n，通常 3~4 | 分裂/合并 | 磁盘 | InnoDB、MyISAM |

**面试追问**：
- 追问：为什么 MySQL 用 B+ 树而不用跳表？→ 答题要点：跳表是链表加多级索引，节点分散、层高随数据增长，一次查询要多次随机访存；B+ 树一个节点就是一页，一次 IO 拿到几百个 key，磁盘友好度差距很大。Redis 用跳表是因为它在内存、且实现比红黑树简单、范围查询方便。
- 追问：B+ 树的树高能不能算得更精确？→ 答题要点：取决于主键类型与行大小。主键越短，一页能放的指针越多，树越矮，这也是"推荐用自增 bigint 而非 UUID 做主键"的原因之一（UUID 是 36 字节字符串，索引项膨胀 4 倍以上）。
- 追问：红黑树插入最多几次旋转？→ 答题要点：插入最多 2 次，删除最多 3 次；但变色可能沿路径上传 O(log n) 次，变色比旋转便宜。
- 追问：为什么自增主键插入不会页分裂？→ 答题要点：自增主键总是追加到最右叶子，顺序写；随机主键会插到中间页，导致页分裂与数据移动，产生大量随机 IO 与碎片。

### Q10. 建堆为什么是 O(n)？TopK 怎么选结构？（中级）

**一句话结论**：完全二叉树可以用数组表示，下标 `i` 的左右孩子是 `2i+1`、`2i+2`，父亲是 `(i-1)/2`。自底向上建堆时，从最后一个非叶子节点（`n/2 - 1`）开始逐个下沉，总代价是各层节点数乘以该层高度之和，这个和收敛到 2n，所以是 O(n) 而不是 O(n log n)。TopK 用容量为 k 的**小顶堆**，时间 O(n log k)、空间 O(k)。

**先把话说白**：建堆看起来是"n 个节点各下沉 log n 层"，所以像是 O(n log n)。但关键事实是：**绝大多数节点在树的底层，而底层节点几乎不用下沉**。越往上节点越少但下沉越深，两个因素互相抵消，求和结果是一个常数倍的 n。

**底层原理**：

1. **数组表示。** 完全二叉树没有空洞，按层序存入数组即可。`i` 从 0 开始：左孩子 `2i+1`，右孩子 `2i+2`，父亲 `(i-1)/2`。最后一个非叶子节点是 `n/2 - 1`，因为下标 ≥ n/2 的节点都是叶子。

2. **建堆的求和。** 高度为 h 的层有约 n/2^(h+1) 个节点，每个节点最多下沉 h 层，总代价 Σ (n/2^(h+1)) · h = n/2 · Σ h/2^h = n/2 · 2 = n。所以是 O(n)。对比"逐个插入建堆"：每次插入上浮 O(log n)，总计 O(n log n)——这才是很多人误答的复杂度。

3. **下沉（siftDown）与上浮（siftUp）。** 建堆用下沉：把当前节点与较大的孩子交换，直到满足堆序。删除堆顶也用下沉。插入用上浮：与父亲比较，比父亲优先就交换。

4. **TopK 的方向。** 求**最大**的 K 个元素，用小顶堆：堆顶是"当前 K 个里最小的"，新元素比堆顶大就替换堆顶并下沉。这样堆里始终保留最大的 K 个。反之求最小 K 个用大顶堆。方向搞反是最高频的错误。

5. **TopK 的两种方案取舍。** ① 小顶堆：O(n log k)，空间 O(k)，适合 n 很大但 k 不大、数据流式到达；② 快速选择（quickselect）：平均 O(n)，但需要一次性拿到全部数据且会修改数组，最坏 O(n²)；③ 全排序：O(n log n)，只有在需要完整有序结果时才用。

6. **堆排序。** 建大顶堆 O(n) → 每次把堆顶与末尾交换，堆大小减一，对新堆顶下沉 O(log n)，共 n 次 → 总 O(n log n)。原地、最坏也是 O(n log n)，但常数比快排大、且是"跳跃访问"，缓存不友好，所以工程中很少用，常用于"要求最坏情况可控"的场景。

```java
// 建堆 + 下沉
private static void siftDown(int[] a, int i, int n) {
    while (true) {
        int l = 2 * i + 1, r = l + 1, max = i;
        if (l < n && a[l] > a[max]) max = l;
        if (r < n && a[r] > a[max]) max = r;
        if (max == i) break;              // 已满足堆序
        int t = a[i]; a[i] = a[max]; a[max] = t;
        i = max;
    }
}
public static void heapSort(int[] a) {
    int n = a.length;
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n);  // O(n) 建堆
    for (int i = n - 1; i > 0; i--) {
        int t = a[0]; a[0] = a[i]; a[i] = t;                 // 堆顶放到末尾
        siftDown(a, 0, i);
    }
}

// TopK：求最大的 k 个，用小顶堆
public static int[] topK(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>(k);    // 默认小顶堆
    for (int x : nums) {
        if (heap.size() < k) heap.offer(x);
        else if (x > heap.peek()) { heap.poll(); heap.offer(x); }
    }
    int[] res = new int[heap.size()];
    for (int i = res.length - 1; i >= 0; i--) res[i] = heap.poll(); // 逆序取出即降序
    return res;
}
```

**易混对比**：

| 目标 | 堆类型 | 判断条件 | 时间 |
| --- | --- | --- | --- |
| 最大的 K 个 | 小顶堆 | 新元素 > 堆顶则替换 | O(n log k) |
| 最小的 K 个 | 大顶堆 | 新元素 < 堆顶则替换 | O(n log k) |
| 第 K 大 | 小顶堆（容量 k） | 最后堆顶即答案 | O(n log k) |
| 数据流中位数 | 大顶堆 + 小顶堆 | 两堆大小差 ≤ 1 | O(log n) 每次 |

**面试追问**：
- 追问：`PriorityQueue` 的 `siftUp` 和 `siftDown` 分别在什么时候用？→ 答题要点：`offer` 用上浮，`poll` 用下沉，`remove(Object)` 用下沉（先找到位置再调整）。
- 追问：为什么 `PriorityQueue` 不是线程安全的？→ 答题要点：内部是无锁的数组操作，并发下会破坏堆序；并发场景用 `PriorityBlockingQueue`。
- 追问：快排的 `partition` 和堆的 `siftDown` 有什么共同点？→ 答题要点：都是"局部调整 + 递归/迭代收敛"，都是原地操作，都依赖交换。

### Q11. 图的存储怎么选？拓扑排序怎么做？（中级）

**一句话结论**：稠密图用邻接矩阵（O(V²) 空间、O(1) 判边），稀疏图用邻接表（O(V+E) 空间、遍历邻居高效）。BFS/DFS 都是 O(V+E)，区别只在"用队列还是栈"。拓扑排序有两种实现：Kahn 算法（统计入度，入度为 0 入队，逐个删边）和 DFS 后序反转；Kahn 天然能检测环（结束时输出节点数 < 总数即有环）。

**先把话说白**：邻接矩阵是"V×V 的表格"，查两人认不认识一眼就知道，但 1 万人就是 1 亿个格子，绝大多数是空的。邻接表是"每个人的好友列表"，只存真实存在的边，省空间但查"某两人是否相邻"要翻列表。社交网络这种稀疏图必须用邻接表。

**底层原理**：

1. **存储结构。** 邻接矩阵 `matrix[i][j] = 1` 表示有边，带权图存权重；空间 O(V²)，适合 V 小于几千且边密集（如 Floyd 最短路）。邻接表 `List<List<Integer>> adj`，空间 O(V+E)；也可以用"链式前向星"（数组模拟链表）进一步减少对象开销，竞赛常用。

2. **BFS 与 DFS 的差异。** BFS 用队列，按层扩展，**无权图**上第一次到达某点即最短路径；DFS 用栈（或递归），一条路走到黑，适合求连通分量、拓扑排序、找环。两者都必须有 `visited` 数组，否则有环图会死循环。

3. **Kahn 拓扑排序。** 统计每个节点入度 → 入度为 0 的入队 → 出队时把它的所有邻居入度减 1，减到 0 就入队 → 队列空时若已输出节点数等于 V，则无环。复杂度 O(V+E)。若要求"按字典序最小的拓扑序"，把队列换成优先队列即可。

4. **DFS 拓扑排序。** 对每个未访问节点 DFS，在**后序位置**（所有邻居处理完之后）把节点加入结果，最后反转结果。正确性来自：若 u → v，则 v 一定先于 u 完成，反转后 u 在 v 前。缺点是环检测需要在递归栈上用三色标记（白 / 灰 / 黑），遇到灰色节点说明有环。

5. **课程表问题的建模。** 课程是节点，先修关系是有向边 `[a, b]` 表示"修 a 前必须修 b"，即 b → a。判断能否修完等价于判断有向图是否有环。

```java
// 课程表：Kahn 算法判断是否有环
public boolean canFinish(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[numCourses];
    for (int[] p : prerequisites) {
        adj.get(p[1]).add(p[0]);   // p[1] -> p[0]
        indeg[p[0]]++;
    }
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < numCourses; i++) if (indeg[i] == 0) q.offer(i);
    int cnt = 0;
    while (!q.isEmpty()) {
        int u = q.poll();
        cnt++;
        for (int v : adj.get(u)) {
            if (--indeg[v] == 0) q.offer(v);   // 入度降为 0 才可入队
        }
    }
    return cnt == numCourses;      // 少于总数说明有环
}
```

**易混对比**：

| 维度 | 邻接矩阵 | 邻接表 |
| --- | --- | --- |
| 空间 | O(V²) | O(V+E) |
| 判断 (u,v) 是否有边 | O(1) | O(degree(u)) |
| 遍历某点所有邻居 | O(V) | O(degree(u)) |
| 适用 | 稠密图、Floyd | 稀疏图、大多数场景 |

**面试追问**：
- 追问：BFS 求最短路径的前提是什么？→ 答题要点：边权相等（无权或权值全为 1）。带权图要用 Dijkstra（非负权）或 Bellman-Ford（可有负权）。
- 追问：Dijkstra 为什么不能处理负权边？→ 答题要点：它基于贪心，认为"已确定的最短距离不会被后续路径改小"，负权边会破坏这个前提。
- 追问：如何判断无向图是否有环？→ 答题要点：并查集，遍历每条边，若两端已连通则成环；或 DFS 记录父节点。

### Q12. 并查集怎么优化到近似 O(1)？（中级）

**一句话结论**：并查集（Union-Find）维护不相交集合，支持"合并两个集合"和"查询元素属于哪个集合"。用**路径压缩**把查找路径上的节点直接挂到根上，用**按秩合并**（或按大小合并）保证树高不失控，两者结合后单次操作的均摊复杂度是 O(α(n))，α 是反阿克曼函数，在实际规模下不超过 4，可视为常数。

**先把话说白**：并查集就是"查户口"。每个人只记自己的父亲，一路往上问就能找到族长。两个人是不是一家，就看族长是不是同一个。合并两家，就是让一个族长认另一个族长当爹。问题是有时候树会退化成一条长链，问一次要爬很久——路径压缩就是"问完之后，把路上所有人都直接挂到族长名下"，下次再问就一步到位。

**底层原理**：

1. **基本结构。** `parent[i]` 表示 i 的父亲，根节点满足 `parent[i] == i`。`find` 沿父亲指针向上直到根；`union(a, b)` 找到两个根，把一个根的父亲设为另一个。

2. **路径压缩。** `find` 递归或迭代地把路径上所有节点直接指向根：`parent[x] = find(parent[x])`。这样树被"压平"，后续查询接近 O(1)。注意路径压缩会破坏"按秩"的高度信息，但因为压缩后树高本来就趋近 1，影响可忽略。

3. **按秩 / 按大小合并。** 合并时把"矮的树"挂到"高的树"下（按秩），或把"小的集合"挂到"大的集合"下（按大小），保证树高 O(log n)。若不做这一步，仅路径压缩在最坏情况下仍有 O(log n) 的单次代价。

4. **复杂度的来源。** Tarjan 证明了路径压缩 + 按秩合并的均摊复杂度是 O(α(n))，α(n) 在 n < 10^600 时都不超过 4。这是"近似 O(1)"的严格出处。

5. **典型应用。** 连通分量计数、Kruskal 最小生成树、判断无向图成环、网络节点连通性（如判断两台机器是否在同一子网）、等式方程可满足性（LeetCode 990）、账户合并。

```java
class UnionFind {
    private final int[] parent;
    private final int[] rank;      // 秩：树高的上界
    private int count;             // 连通分量个数

    public UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        count = n;
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    public int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);  // 路径压缩
        return parent[x];
    }

    public boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;                        // 已连通，说明这条边会成环
        if (rank[ra] < rank[rb])      parent[ra] = rb;     // 矮的挂高的
        else if (rank[ra] > rank[rb]) parent[rb] = ra;
        else { parent[rb] = ra; rank[ra]++; }              // 等高时秩加一
        count--;
        return true;
    }

    public boolean connected(int a, int b) { return find(a) == find(b); }
}
```

**易混对比**：

| 优化组合 | 单次复杂度 | 说明 |
| --- | --- | --- |
| 朴素 | O(n) | 可能退化成链 |
| 只有按秩合并 | O(log n) | 树高受控 |
| 只有路径压缩 | 均摊 O(log n) | 最坏仍可能较深 |
| 两者结合 | 均摊 O(α(n)) ≈ O(1) | 理论最优 |

**面试追问**：
- 追问：路径压缩为什么用递归不会栈溢出？→ 答题要点：压缩后树高趋近 1，递归深度很小；但初始若构造出长链，首次 find 可能较深，工程上可改迭代两趟写法。
- 追问：并查集能支持"分裂"吗？→ 答题要点：不能，只支持合并。需要分裂要用可持久化并查集或 LCT（Link-Cut Tree）。
- 追问：Kruskal 里并查集起什么作用？→ 答题要点：判断加入一条边是否会成环，若两端已连通则跳过，保证生成的是树。

### Q13. 各排序算法的复杂度与稳定性？工程上怎么选？（中级）

**一句话结论**：基于比较的排序下界是 Ω(n log n)，归并和堆排能达到；快排平均 O(n log n) 但最坏 O(n²)；计数/基数/桶排不是比较排序，能突破下界但要求数据有额外结构（范围有限、可按位分配）。稳定性指相等元素的相对顺序是否保持：归并、插入、冒泡、计数、基数稳定；快排、堆排、选择、希尔不稳定。

**先把话说白**：稳定性不是学术概念，它在业务里非常实在。比如订单列表"先按下单时间排，再按金额排"，如果第二次排序不稳定，同金额的订单时间顺序就乱了。Java 对**对象数组**用 TimSort（稳定），对**基本类型数组**用双轴快排（不稳定）——因为基本类型没有"身份"，相等就是相等，稳定与否无意义，而快排更快更省内存。

**底层原理**：

1. **复杂度与稳定性总表。**

| 算法 | 平均 | 最坏 | 最好 | 空间 | 稳定 | 适用 |
| --- | --- | --- | --- | --- | --- | --- |
| 冒泡 | O(n²) | O(n²) | O(n) | O(1) | 是 | 教学，几乎不用 |
| 插入 | O(n²) | O(n²) | O(n) | O(1) | 是 | 小数组、近乎有序 |
| 选择 | O(n²) | O(n²) | O(n²) | O(1) | 否 | 交换次数敏感场景 |
| 希尔 | O(n^1.3) 左右 | O(n²) | O(n log n) | O(1) | 否 | 中等规模、嵌入式 |
| 归并 | O(n log n) | O(n log n) | O(n log n) | O(n) | 是 | 稳定排序、外部排序、链表 |
| 快排 | O(n log n) | O(n²) | O(n log n) | O(log n) | 否 | 通用内存排序 |
| 堆排 | O(n log n) | O(n log n) | O(n log n) | O(1) | 否 | 最坏可控、TopK |
| 计数 | O(n+k) | O(n+k) | O(n+k) | O(k) | 是 | 整数且范围小 |
| 基数 | O(d(n+k)) | O(d(n+k)) | O(d(n+k)) | O(n+k) | 是 | 定长整数/字符串 |
| 桶排 | O(n+k) | O(n²) | O(n) | O(n+k) | 视实现 | 均匀分布浮点数 |

2. **为什么比较排序下界是 O(n log n)。** 决策树模型：n 个元素有 n! 种排列，每次比较只能二分，树高至少 log₂(n!) ≈ n log n。所以任何基于比较的算法都不可能更快，这是信息论下界，不是工程限制。

3. **插入排序为什么在近乎有序时是 O(n)。** 每次只与前一个比较，若已有序则内层循环一次就退出，总比较次数 n-1。JDK 在数组很短（双轴快排里小于 47）或检测到数据"高度结构化"时会退化到插入排序。

4. **Java 的实现选择。** `Arrays.sort(int[])` 用双轴快排（Dual-Pivot Quicksort，JDK 7 引入），选两个 pivot 把数组分三段，减少比较次数、对重复元素更友好；JDK 14 起对小数组和结构化数据引入了更多混合策略。`Arrays.sort(Object[])` 用 TimSort：先识别天然有序的 run，再用归并合并 run，最好情况 O(n)，最坏 O(n log n)，稳定。`Collections.sort` 委托给 `List.sort`，最终也是 TimSort。

5. **工程选型的三问。** ① 数据量多大？小于几十个用插入排序。② 是否要求稳定？要求就用归并/TimSort。③ 内存是否紧张、是否要求最坏可控？用堆排。④ 数据是否有结构（整数范围小）？用计数/基数。⑤ 数据是否放不下内存？用外部归并排序。

6. **外部排序。** 大文件排序的标准做法：分块读入内存排序后写临时文件（形成多个有序 run），再做 k 路归并（用大小为 k 的堆选最小）。这就是数据库 `ORDER BY` 落盘、Hadoop MapReduce 的 shuffle 阶段、`sort` 命令处理超大文件的做法。

**易混对比**：

| 场景 | 推荐算法 | 理由 |
| --- | --- | --- |
| 基本类型数组 | 双轴快排 | 不稳定无影响，常数小、原地 |
| 对象数组 / 业务排序 | TimSort | 稳定，能利用已有顺序 |
| 要求最坏 O(n log n) 且内存紧张 | 堆排 | 原地且最坏可控 |
| 链表排序 | 归并 | 链表归并不需要随机访问，可做到 O(1) 额外空间 |
| 千万级整数、范围 0~1000 | 计数排序 | O(n+k) 线性 |
| 超出内存的大文件 | 外部归并 | 分块 + k 路归并 |

**面试追问**：
- 追问：为什么 `Arrays.sort(int[])` 不用归并？→ 答题要点：归并需要 O(n) 额外空间，基本类型不稳定无所谓，快排原地且更快；对象数组才需要稳定性。
- 追问：TimSort 的"最好 O(n)"怎么来的？→ 答题要点：先扫描识别升序或降序的 run（降序就地反转），若整个数组就是一个 run，直接返回。
- 追问：快排和归并的分治有什么本质区别？→ 答题要点：快排是"先划分再递归"（分治在划分时完成，合并无需操作），归并是"先递归再合并"（划分 trivial，工作在合并）。

### Q14. 快排最坏情况怎么产生？三路划分解决什么？（高级）

**一句话结论**：快排的最坏情况是每次划分都极不均衡（比如数组已有序且固定取首元素为 pivot），递归深度退化为 n，时间 O(n²)、栈空间 O(n)。解决办法是**随机化 pivot** 或三数取中，把最坏情况的触发概率压到可忽略；**三路划分**（小于 / 等于 / 大于）解决的是"大量重复元素"导致的无效递归，把等于 pivot 的元素一次性归位，重复元素多时能降到 O(n)。

**先把话说白**：快排的核心是"选一个基准，把小的扔左边、大的扔右边"。如果每次选的基准恰好是最小值，那左边为空、右边 n-1 个，等于每次只消灭一个元素——这就是 O(n²)。而如果数组里有大量相同的值，二路划分会把它们反复分到同一侧，做大量无用功；三路划分直接把"等于基准"的一堆全部钉在原地，不再参与递归。

**底层原理**：

1. **Lomuto 分区（最易写）。** 取末尾元素为 pivot，用 `i` 记录"小于区的右边界"，遍历 `j`，遇到小于 pivot 的就 `swap(a[++i], a[j])`，最后 `swap(a[i+1], a[high])`。返回 `i+1` 即 pivot 的最终位置。缺点：对重复元素退化为 O(n²)（所有等于 pivot 的元素都被分到一侧）。

2. **Hoare 分区（更高效）。** 双指针从两端向中间走，左指针找 ≥ pivot 的，右指针找 ≤ pivot 的，交换，直到相遇。交换次数更少，且对重复元素更友好，但边界极难写对（`i <= j` 还是 `i < j`、返回 `j` 还是 `i`），是面试翻车高发区。

3. **三路划分（Dutch National Flag）。** 维护三个区间：`[0, lt)` 小于、`[lt, i)` 等于、`(gt, n-1]` 大于。遍历时：小于 pivot 就与 `lt` 交换并 `lt++`、`i++`；大于就与 `gt` 交换并 `gt--`（注意此时 `i` 不前进，因为换过来的是未检查元素）；等于就 `i++`。结束后只需递归 `[0, lt)` 和 `(gt, n-1]`，中间相等的部分不再处理。

4. **最坏情况的三种来源。** ① 输入已有序或逆序 + 固定取首/尾为 pivot；② 所有元素相等（二路划分下每次只减少 1 个）；③ 攻击者构造的"快排杀手"序列（AntiQuicksort），可使任何确定性 pivot 策略退化，这是 DoS 的一种。所以生产实现必须随机化。

5. **随机化的效果。** 随机选 pivot 后，期望的划分比例是常数级均衡，期望复杂度 O(n log n)，且与输入分布无关。严格来说"最坏 O(n²)"仍然存在，但触发概率极低。工程上常用"三数取中"（首、中、尾取中位数）作为低成本近似。

6. **递归深度与栈。** 即使平均 O(log n) 深度，最坏也是 O(n)。优化手段：**先递归较短的一侧，较长的一侧用循环（尾递归消除）**，可把栈深度稳定在 O(log n)。

```java
// 三路划分快排：随机 pivot，处理大量重复元素
public static void quickSort(int[] a, int lo, int hi) {
    while (lo < hi) {
        int pivot = a[lo + ThreadLocalRandom.current().nextInt(hi - lo + 1)]; // 随机基准
        int lt = lo, i = lo, gt = hi;
        while (i <= gt) {
            if (a[i] < pivot)      swap(a, lt++, i++);
            else if (a[i] > pivot) swap(a, i, gt--);   // i 不前进，换来的元素未检查
            else                   i++;
        }
        // 此时 [lo, lt) < pivot，[lt, gt] == pivot，(gt, hi] > pivot
        if (lt - lo < hi - gt) {          // 先递归短的一侧，控制栈深
            quickSort(a, lo, lt - 1);
            lo = gt + 1;                   // 长的一侧用循环
        } else {
            quickSort(a, gt + 1, hi);
            hi = lt - 1;
        }
    }
}
private static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
```

**易混对比**：

| 分区方式 | 重复元素表现 | 交换次数 | 边界难度 | 典型用途 |
| --- | --- | --- | --- | --- |
| Lomuto | 差，退化 O(n²) | 多 | 低 | 教学、面试手写 |
| Hoare | 较好 | 少 | 高 | 经典实现 |
| 三路划分 | 优，重复多时 O(n) | 中 | 中 | 工程实现、带大量重复的数据 |

**面试追问**：
- 追问：快排什么时候最慢？→ 答题要点：每次划分极不均衡时，如已排序数组 + 固定端点 pivot，或大量重复元素 + 二路划分。
- 追问：为什么快排比堆排快，明明都是 O(n log n)？→ 答题要点：快排是顺序访问、缓存友好，常数小；堆排每次下沉都是跳跃访问（`2i+1`），缓存命中率低。
- 追问：如何在不修改原数组的前提下排序？→ 答题要点：复制一份再排，或改用归并（归并本身需要额外空间但可以不改原数组）。
- 追问：三路划分中为什么 `a[i] > pivot` 时 `i` 不前进？→ 答题要点：从 `gt` 换过来的元素还没被检查过，必须留在原位重新判断。

### Q15. 二分边界怎么写才不出错？什么是二分答案？（中级）

**一句话结论**：二分的本质是"在一个**单调**的判定上缩小范围"。写法上统一采用**左闭右开** `[lo, hi)`：循环条件 `lo < hi`，`mid = lo + (hi - lo) / 2`，根据判定把区间改成 `[mid+1, hi)` 或 `[lo, mid)`，循环结束时 `lo == hi` 即答案位置。二分答案则是"对答案本身二分"，只要能把问题转成"给定 x，是否可行"的单调判定，就能用 O(log range) 次判定求解。

**先把话说白**：二分红的是"答案在哪"。左闭右开的好处是：区间长度就是 `hi - lo`，空区间是 `lo == hi`，不会出现"最后一个元素永远处理不到"或"死循环在 lo == hi"的问题。很多人写 `while (lo <= hi)` 配 `lo = mid`，一旦 `mid == lo` 就死循环——根源是区间语义和更新方式没对齐。

**底层原理**：

1. **两种语义。** ① 找"第一个满足条件的"（lowerBound）：条件在右侧恒真，答案是最左的真位置；② 找"最后一个满足条件的"（upperBound - 1）。二者是对偶的，写清"我要找哪一个"比背模板重要。

2. **左闭右开的三个不变量。** `[0, lo)` 内一定不满足（或一定小于目标）；`[hi, n)` 内一定满足（或一定大于目标）；`[lo, hi)` 是待搜索区间。每次迭代必须缩小 `hi - lo`，且不能破坏前两条。

3. **`mid` 的溢出问题。** `(lo + hi) / 2` 在 `lo`、`hi` 都接近 `Integer.MAX_VALUE` 时会溢出为负数，导致数组越界。必须写 `lo + (hi - lo) / 2`。这是 JDK 里 `Arrays.binarySearch` 曾经修复过的真实 bug。

4. **lowerBound 与 upperBound。** `lowerBound(t)`：第一个 ≥ t 的位置；`upperBound(t)`：第一个 > t 的位置。二者相减就是 t 的出现次数。Java 没有内置这两个函数，`Arrays.binarySearch` 返回的是"找到的任意一个位置"，找不到时返回 `-(插入点) - 1`，语义不同，不能混用。

5. **旋转数组。** 有序数组被旋转后，`nums[mid]` 与 `nums[lo]` 比较可以判断哪一半有序：若 `nums[lo] <= nums[mid]`，左半有序，看 target 是否落在 `[nums[lo], nums[mid])` 内决定往哪边走。有重复元素时（如 `[1,0,1,1,1]`）无法判断，只能 `lo++` 缩小区间，最坏退化为 O(n)。

6. **二分答案的识别信号。** 题目问"最小化最大值""最大化最小值""最少需要多少""能否在 x 内完成"——这类"答案具有单调性"的问题，把答案当作自变量，写一个 `check(x)` 返回布尔值，然后二分答案。判定函数通常是 O(n) 的贪心或模拟，总复杂度 O(n log range)。

7. **浮点二分。** 不能用 `lo < hi`，要固定迭代次数（如 100 次）或判断 `hi - lo < 1e-6`，避免精度导致的死循环。

```java
// 左闭右开：lowerBound 返回第一个 >= target 的下标，不存在则返回 n
public static int lowerBound(int[] a, int target) {
    int lo = 0, hi = a.length;          // [lo, hi)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;   // 防溢出
        if (a[mid] < target) lo = mid + 1;  // mid 不满足，排除
        else                 hi = mid;      // mid 可能满足，保留
    }
    return lo;                           // lo == hi，即插入点
}

// 二分答案：把 n 根绳子切成等长的 k 段，求每段最大长度（保留两位小数）
public static double maxLen(double[] ropes, int k) {
    double lo = 0, hi = 0;
    for (double r : ropes) hi = Math.max(hi, r);
    for (int iter = 0; iter < 100; iter++) {     // 固定迭代次数，避免精度死循环
        double mid = (lo + hi) / 2;
        int cnt = 0;
        for (double r : ropes) cnt += (int) (r / mid);
        if (cnt >= k) lo = mid; else hi = mid;   // 可行则尝试更大
    }
    return lo;
}
```

**易混对比**：

| 目标 | 判定 | 更新方式 | 返回 |
| --- | --- | --- | --- |
| lowerBound（第一个 ≥ t） | `a[mid] < t` | `lo = mid + 1` / `hi = mid` | `lo` |
| upperBound（第一个 > t） | `a[mid] <= t` | `lo = mid + 1` / `hi = mid` | `lo` |
| 找任意一个 = t | `a[mid] == t` | 直接返回 | `mid` |
| 二分答案（最小可行） | `check(mid)` 为真 | `hi = mid` / `lo = mid + 1` | `lo` |
| 二分答案（最大可行） | `check(mid)` 为真 | `lo = mid` / `hi = mid - 1` | `lo` |

**面试追问**：
- 追问：`while (lo <= hi)` 和 `while (lo < hi)` 怎么选？→ 答题要点：闭区间 `[lo, hi]` 配 `lo <= hi`，更新必须 `lo = mid + 1` 或 `hi = mid - 1`；左闭右开配 `lo < hi`，更新可以是 `hi = mid`。混用就会死循环。
- 追问：为什么 `mid` 要向下取整？→ 答题要点：区间只有 2 个元素时，向上取整会让 `mid == hi`，若更新是 `lo = mid` 则区间不缩小，死循环。
- 追问：二分一定能找到答案吗？→ 答题要点：前提是单调性成立。若判定函数不单调（如"能切出 k 段"在长度过大时反而不成立是正常的，但中间不能有反复），二分结果无意义。

### Q16. 动态规划怎么想到状态定义？（高级）

**一句话结论**：DP 的三要素是**状态定义、状态转移、边界初始化**，其中状态定义最难。想状态的通用路径是：找"最后一步"是什么 → 用一个或几个变量描述"处理到哪了" → 验证是否满足**无后效性**（当前状态确定后，后续决策不依赖到达它的路径）→ 由依赖关系决定遍历顺序（依赖小下标就正序，依赖上一行就滚动数组，依赖大下标就倒序）。

**先把话说白**：DP 就是"把大问题拆成一串小问题，并把小问题的答案记下来"。难点不在写代码，而在"记什么"。记的东西必须足够描述当前局面——记少了会漏信息（状态不足），记多了会重复计算（状态冗余）。判断标准是：只要这个状态定了，后面的最优决策就与"怎么走到这里的"无关。

**底层原理**：

1. **识别信号。** ① 求"最优/计数/可行性"；② 问题可以按某个维度（位置、容量、长度）逐层推进；③ 有重叠子问题（递归会重复计算）。三者同时满足才考虑 DP，否则可能是贪心或分治。

2. **状态定义的三个层次。** 一维：`dp[i]` 表示"前 i 个元素的最优解"；二维：`dp[i][j]` 表示"前 i 个元素、约束为 j 时的最优解"；带额外维度：如股票问题需要 `dp[i][0/1]` 表示"第 i 天持股/不持股"。维度来源于"决策会影响哪些约束"。

3. **无后效性的检验方法。** 问自己："如果两个不同的路径到达了同一个状态，它们的后续最优解是否相同？"如果相同，状态设计正确；如果不同，说明状态缺信息（典型：需要记录"上一个选了什么"）。股票问题里"是否持股"就是必须记录的信息。

4. **遍历顺序由依赖决定。** 0-1 背包的 `dp[j]` 依赖上一轮的 `dp[j - w[i]]`，若正序遍历，`dp[j-w]` 可能已经被本轮更新过（等于同一物品用了多次），所以必须**倒序**；完全背包允许重复使用，正是要利用"已更新"的值，所以**正序**。这个细节是背包问题最常考的点。

5. **初始化与边界。** `dp[0]` 的语义要明确：背包容量为 0 时价值为 0；LIS 中 `dp[i]` 至少为 1（自身）；编辑距离中 `dp[i][0] = i`、`dp[0][j] = j`。初始化错了，后面全错。

6. **空间优化。** 若 `dp[i][*]` 只依赖 `dp[i-1][*]`，可以压成一维（滚动数组）；若还依赖 `dp[i][j-1]`（同一行左侧），则一维数组要保证左侧已被更新，倒序/正序的选择由此决定。

**以三个经典问题为例**：

**0-1 背包**：`dp[j]` = 容量为 j 时能装的最大价值。对每个物品，倒序遍历 j：`dp[j] = max(dp[j], dp[j-w] + v)`。倒序保证每件物品只用一次。

**最长递增子序列（LIS）**：`dp[i]` = 以 `nums[i]` **结尾**的 LIS 长度（注意"结尾"这个限定是无后效性的关键）。转移：`dp[i] = max(dp[j]) + 1`，其中 `j < i` 且 `nums[j] < nums[i]`。O(n²)。优化到 O(n log n)：维护 `tails[len]` 表示"长度为 len+1 的递增子序列的最小结尾值"，遍历时二分查找插入位置，`tails` 天然单调递增。

**编辑距离**：`dp[i][j]` = 把 `word1` 前 i 个字符变成 `word2` 前 j 个字符的最少操作数。若 `word1[i-1] == word2[j-1]`，`dp[i][j] = dp[i-1][j-1]`；否则 `min(删除 dp[i-1][j], 插入 dp[i][j-1], 替换 dp[i-1][j-1]) + 1`。三个方向分别对应三种操作，这是"最后一步"思路的直接体现。

```java
// 0-1 背包：一维滚动，容量必须倒序
public static int knapsack(int[] w, int[] v, int cap) {
    int[] dp = new int[cap + 1];              // dp[j]：容量 j 的最大价值
    for (int i = 0; i < w.length; i++) {
        for (int j = cap; j >= w[i]; j--) {   // 倒序：保证物品只用一次
            dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
        }
    }
    return dp[cap];
}

// LIS：O(n log n) 的 tails 写法
public static int lengthOfLIS(int[] nums) {
    int[] tails = new int[nums.length];
    int len = 0;                              // tails 的有效长度
    for (int x : nums) {
        int lo = 0, hi = len;                 // 在 [0, len) 中找第一个 >= x 的位置
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (tails[mid] < x) lo = mid + 1; else hi = mid;
        }
        tails[lo] = x;                        // 替换或追加
        if (lo == len) len++;
    }
    return len;
}
```

**易混对比**：

| 问题 | 状态定义 | 遍历顺序 | 关键点 |
| --- | --- | --- | --- |
| 0-1 背包 | `dp[j]` 容量 j 的最大价值 | 容量倒序 | 每件物品只能用一次 |
| 完全背包 | `dp[j]` 同上 | 容量正序 | 正序即允许重复使用 |
| LIS | `dp[i]` 以 i 结尾的长度 | 正序 | "以 i 结尾"保证无后效性 |
| 编辑距离 | `dp[i][j]` 前缀间距离 | 双重正序 | 三种操作对应三个方向 |

**面试追问**：
- 追问：0-1 背包为什么必须倒序？→ 答题要点：正序时 `dp[j-w]` 已被本轮更新，相当于把当前物品又放了一次，变成了完全背包。
- 追问：LIS 的 `tails` 数组是真正的 LIS 吗？→ 答题要点：不是，`tails[i]` 只是"长度为 i+1 的递增子序列的最小结尾"，长度正确但内容不一定是某条真实路径，要还原需额外记录前驱。
- 追问：DP 和记忆化搜索的关系？→ 答题要点：本质相同，记忆化是自顶向下 + 缓存，DP 是自底向上 + 填表；记忆化只计算可达状态，DP 会算所有状态，但常数更小、便于空间优化。

### Q17. KMP 的 next 数组到底是什么？（高级）

**一句话结论**：`next[i]`（也叫失配函数、前缀函数）表示模式串 `pattern[0..i]` 这个子串的**最长相等前后缀的长度**。匹配失配时，文本指针不回退，模式串指针跳到 `next[j-1]`，从而把暴力匹配的 O(nm) 降到 O(n+m)。理解 next 的关键是：它记录了"已经匹配成功的那部分里，有哪些前缀同时也是后缀"，可以直接复用。

**先把话说白**：暴力匹配在失配时把模式串整体右移一位、从头再来，浪费了"前面明明已经匹配上了"这个信息。KMP 的想法是：既然前 j 个字符已经匹配，那这 j 个字符的某个前缀如果等于它的后缀，我就把模式串滑到那个前缀的位置继续比，文本指针一步不退。

**底层原理**：

1. **前缀与后缀的定义。** 对字符串 `s`，前缀是去掉若干尾部字符、长度 < |s| 的子串；后缀是去掉若干头部字符、长度 < |s| 的子串。"相等前后缀"要求长度相同且内容相同。

2. **next 的递推求法。** `next[0] = 0`。对 `i ≥ 1`，令 `j = next[i-1]`，若 `pattern[i] == pattern[j]`，则 `next[i] = j + 1`；否则令 `j = next[j-1]` 继续回退，直到匹配或 `j == 0`（此时 `next[i] = 0`）。这个回退过程是均摊 O(1) 的，总构建时间 O(m)。

3. **匹配过程。** 文本指针 `i` 单调前进；模式指针 `j` 在失配时跳到 `next[j-1]`。因为 `j` 每次跳都会严格减小，而 `i` 只增不减，总比较次数 O(n+m)。

4. **为什么 next 能保证不漏解。** 设已匹配 `pattern[0..j-1]`，失配于 `pattern[j]`。若存在更小的偏移使匹配继续，那个偏移对应的前缀必须等于当前已匹配串的某个后缀——而 `next[j-1]` 给出的正是最长的那一个。选最长的可以保证不跳过任何可能的匹配位置。

5. **next 与"最小循环节"。** 若 `n % (n - next[n-1]) == 0`，则最小循环节长度为 `n - next[n-1]`。这是 KMP 的一个常见推论题（如"重复的子字符串"）。

```java
// 构建 next：next[i] = pattern[0..i] 的最长相等前后缀长度
private static int[] buildNext(String p) {
    int m = p.length();
    int[] next = new int[m];
    int j = 0;                                  // j 是当前候选前缀长度
    for (int i = 1; i < m; i++) {
        while (j > 0 && p.charAt(i) != p.charAt(j)) j = next[j - 1]; // 回退
        if (p.charAt(i) == p.charAt(j)) j++;
        next[i] = j;
    }
    return next;
}

// 匹配：返回第一次出现的下标，找不到返回 -1
public static int kmp(String s, String p) {
    if (p.isEmpty()) return 0;
    int[] next = buildNext(p);
    int j = 0;
    for (int i = 0; i < s.length(); i++) {
        while (j > 0 && s.charAt(i) != p.charAt(j)) j = next[j - 1];
        if (s.charAt(i) == p.charAt(j)) j++;
        if (j == p.length()) return i - p.length() + 1;  // 完整匹配
    }
    return -1;
}
```

**易混对比**：

| 方案 | 预处理 | 匹配 | 是否回退文本指针 | 适用 |
| --- | --- | --- | --- | --- |
| 暴力 | 无 | O(nm) | 是 | 短串 |
| KMP | O(m) | O(n+m) | 否 | 单模式、流式 |
| BM | O(m) | 平均 O(n/m) 级 | 可跳跃 | 长文本、编辑器查找 |
| Trie | O(总长) | O(m) | 不适用 | 多模式前缀查询 |
| AC 自动机 | O(总长) | O(n + 匹配数) | 否 | 多模式同时匹配 |

**面试追问**：
- 追问：为什么 KMP 在实际工程里不常用？→ 答题要点：常数大、实现易错；实际多用 BM（跳着比）或标准库的优化实现（如 glibc 的 `memmem`、Rust 的 two-way 算法）。
- 追问：Trie 适合什么场景？→ 答题要点：前缀查询、自动补全、敏感词过滤（配合 AC 自动机）、IP 路由表的最长前缀匹配。
- 追问：字符串哈希的原理与风险？→ 答题要点：把字符串视为 base 进制数取模，`hash(l,r) = h[r] - h[l-1] * base^(r-l+1)`，可 O(1) 比较子串；风险是哈希碰撞，需要双模数或随机 base 降低概率。

### Q18. 高频手撕题有哪些固定解法？（中级）

**一句话结论**：手撕题的价值在于"套路识别"——看到"缓存淘汰"就想到哈希 + 双向链表，看到"链表找环/中点"就想到快慢指针，看到"两数之和"就想到哈希表，看到"去重三元组"就想到排序 + 双指针，看到"网格连通块"就想到 DFS 染色。把套路记牢，剩下的是边界处理。

**先把话说白**：面试手撕不是让你现场发明算法，而是让你在 15 分钟内写出无 bug 的经典结构。所以准备方式不是"刷 500 题"，而是"把 10 类模板各写 3 遍，直到能默写"。

**底层原理（逐类要点）**：

1. **LRU 缓存**：`HashMap<key, Node>` + 双向链表（头是最近使用，尾是最久未用）。`get` 命中则把节点移到头部；`put` 若超容则删尾节点并同步删 map。用哨兵头尾节点可以省掉大量判空。Java 也可用 `LinkedHashMap` 的 `accessOrder=true` 加 `removeEldestEntry` 三行实现，但面试要求手写。

2. **反转链表**：三指针 `prev / cur / next`，循环中先存 `next`，再改 `cur.next = prev`，最后整体后移。递归写法是"先反转后面，再让 head.next.next = head，head.next = null"，注意递归深度。

3. **合并两个有序链表**：哨兵节点 + 尾指针，谁小接谁，最后接上剩余部分。哨兵能消除"第一个节点"的特判。

4. **环形链表**：快慢指针，慢走 1 步、快走 2 步，相遇则有环。找入口：相遇后一个指针回到 head，两者同速前进，再次相遇即入口（推导：设头到入口距离 a，入口到相遇点 b，环长 L，则 `a + b + kL = 2(a + b)`，得 `a = kL - b`）。

5. **二叉树最大深度**：后序，`1 + max(left, right)`；层序遍历数层数也可。

6. **两数之和**：哈希表存"值 → 下标"，遍历时查 `target - x` 是否存在。O(n) 时间、O(n) 空间。要求返回下标就不能排序（排序会丢原始下标）。

7. **三数之和**：排序 + 固定第一个数 + 双指针。去重是关键：第一个数跳过重复，双指针移动后也要跳过重复。O(n²)。

8. **接雨水**：三种解法——① 双指针 + 左右最大高度，O(n)/O(1)；② 单调栈按层计算；③ 预处理左右最大值数组。双指针写法最短：`ans += min(leftMax, rightMax) - height[i]`。

9. **岛屿数量**：遍历网格，遇到 `'1'` 就计数 +1 并 DFS 把连通块全部标记为 `'0'`（染色）。O(mn)。大规模数据用 BFS 防递归栈溢出，或用并查集。

10. **全排列**：回溯 + `used` 数组，或交换法（`swap(i, start)` 后递归 `start+1` 再换回）。有重复元素时先排序，同层跳过 `nums[i] == nums[i-1] && !used[i-1]`。

11. **生产者消费者**：`BlockingQueue` 是最简写法；手写则用 `ReentrantLock` + 两个 `Condition`（`notFull` / `notEmpty`），`await` 必须放在 `while` 循环里防虚假唤醒。

```java
// LRU：哈希表 + 双向链表（带哨兵）
class LRUCache {
    private static class Node {
        int k, v; Node prev, next;
        Node(int k, int v) { this.k = k; this.v = v; }
    }
    private final Map<Integer, Node> map = new HashMap<>();
    private final int cap;
    private final Node head = new Node(0, 0), tail = new Node(0, 0); // 哨兵

    public LRUCache(int capacity) {
        this.cap = capacity;
        head.next = tail; tail.prev = head;      // 头=最近使用，尾=最久未用
    }
    public int get(int key) {
        Node n = map.get(key);
        if (n == null) return -1;
        moveToHead(n);                            // 访问即提升优先级
        return n.v;
    }
    public void put(int key, int value) {
        Node n = map.get(key);
        if (n != null) { n.v = value; moveToHead(n); return; }
        if (map.size() == cap) {                  // 超容：淘汰尾节点
            Node old = tail.prev;
            remove(old); map.remove(old.k);
        }
        Node node = new Node(key, value);
        map.put(key, node); addFirst(node);
    }
    private void remove(Node n) { n.prev.next = n.next; n.next.prev = n.prev; }
    private void addFirst(Node n) {
        n.next = head.next; n.prev = head;
        head.next.prev = n; head.next = n;
    }
    private void moveToHead(Node n) { remove(n); addFirst(n); }
}
```

**易混对比**：

| 题型 | 核心结构 | 复杂度 | 易错点 |
| --- | --- | --- | --- |
| LRU | 哈希 + 双向链表 | get/put O(1) | 忘记同步删 map、哨兵初始化 |
| 反转链表 | 三指针 | O(n)/O(1) | 丢失 next 指针导致断链 |
| 环形链表 | 快慢指针 | O(n)/O(1) | 判断条件要检查 `fast.next != null` |
| 三数之和 | 排序 + 双指针 | O(n²) | 三处去重漏一处就重复 |
| 接雨水 | 双指针 | O(n)/O(1) | 更新答案与更新边界的顺序 |
| 全排列 | 回溯 | O(n·n!) | 撤销选择、重复元素剪枝 |

**面试追问**：
- 追问：LRU 的 `get` 为什么也要移动节点？→ 答题要点：LRU 按"最近使用"淘汰，读操作也算使用；若不移动就退化成 FIFO。
- 追问：如何实现 LFU？→ 答题要点：需要"频次 → 双向链表"的桶，外加 `minFreq` 指针，O(1) 实现较复杂；常见简化版用优先队列 O(log n)。
- 追问：生产者消费者里为什么 `await` 要放在 `while` 而不是 `if`？→ 答题要点：防止虚假唤醒（spurious wakeup）与被其他线程抢先消费，醒来后必须重新检查条件。

### Q19. 海量数据的 TopK、去重、排序怎么做？（高级）

**一句话结论**：海量数据处理的核心是"内存放不下，就必须分治或近似"。TopK 用容量 k 的小顶堆（单机流式）或"哈希分片 + 各片 TopK + 归并"（分布式）；去重用 Bitmap（整数且范围可控）或布隆过滤器（允许误判、极致省内存）；排序用外部归并（分块排序 + k 路归并）；频率统计用"哈希分片到多台/多文件 + 各片统计 + 合并"。

**先把话说白**：数据量大到装不进内存时，只有两条路：要么**不装全部**（用近似结构，牺牲精确性换空间），要么**分成能装下的块**（分治，牺牲一次额外的读写）。所有海量数据题的答案都是这两条路的组合。

**底层原理**：

1. **TopK 的单机解法。** 维护容量为 k 的小顶堆，遍历一遍，O(n log k) 时间、O(k) 空间。k 很小时（如 k=100）几乎不占内存，可以处理任意大的流。若 k 也很大（如取前 1000 万），单机堆放不下，改用 quickselect 分治：按 pivot 分成两段，只递归包含第 k 大的那一段，期望 O(n)。

2. **TopK 的分布式解法。** 按 key 哈希把数据分到 m 个节点，每个节点算本地 TopK，最后把 m×k 个候选汇总再算一次全局 TopK。注意：**按 key 哈希**保证同一 key 落到同一节点，这对"频率统计"是必须的；但如果只是"全局最大的 k 个值"，直接各节点 TopK 再归并即可，不需要哈希。

3. **Bitmap 的算术。** 40 亿个 int 去重，若用 `HashSet<Integer>`，每个 Integer 对象约 16 字节 + HashSet 的 Entry 开销，至少几十 GB。用 Bitmap：40 亿 bit = 4×10⁹ / 8 = 500 MB。位图下标即数值，`set(i)` 把第 i 位置 1。缺点是要求数值范围可控且较稠密，稀疏数据会浪费。

4. **布隆过滤器的原理与代价。** 用 m 位的位数组 + k 个独立哈希函数。插入时把 k 个位置置 1；查询时若 k 个位置全为 1 则"可能存在"，否则"一定不存在"。误判率约 `(1 - e^(-kn/m))^k`，在 k = 0.7m/n 时最优。**不支持删除**（一个位可能被多个元素共享），需要删除用计数布隆过滤器或 Cuckoo Filter。典型用途：缓存穿透防护、爬虫 URL 去重、推荐系统已读过滤。

5. **外部排序的流程。** ① 把大文件按内存上限切成若干块，每块读入内存排序后写成有序的临时文件（run）；② 对这些 run 做 k 路归并，用大小为 k 的小顶堆每次取最小，输出到最终文件。若 run 数量超过可同时打开的文件数，需要多轮归并。总 IO 约 2 × 数据量 × 归并轮数。

6. **频率统计（TopK 热词）。** 哈希分片：`hash(word) % m` 把词分到 m 个文件，保证同一个词只出现在一个文件里；每个文件单独用 HashMap 统计词频并取 TopK；最后合并 m 个 TopK 取全局前 k。这样每片都能装进内存。

7. **近似统计的进阶结构。** 基数估计用 HyperLogLog（12 KB 可估计上亿 UV，误差约 0.81%）；频率估计用 Count-Min Sketch（固定宽高的计数矩阵，取最小值，只会高估不会低估）；这两个是 Redis（`PFADD`）和大数据平台的常用组件。

**易混对比**：

| 需求 | 结构 | 空间 | 精确性 | 备注 |
| --- | --- | --- | --- | --- |
| 整数去重（范围可控） | Bitmap | 范围/8 字节 | 精确 | 40 亿 int ≈ 500 MB |
| 任意元素去重（允许误判） | 布隆过滤器 | 约 10 bit/元素 | 有假阳性 | 不支持删除 |
| TopK（k 小） | 小顶堆 | O(k) | 精确 | 流式、单机 |
| TopK（k 大） | quickselect / 分治 | O(n) | 精确 | 需全量数据 |
| 基数统计（UV） | HyperLogLog | 12 KB | 约 0.81% 误差 | Redis PFADD |
| 频率统计 | 分片 + HashMap | 单片可容纳 | 精确 | 同 key 必须同片 |

**面试追问**：
- 追问：布隆过滤器为什么不能删除？→ 答题要点：多个元素共享同一位，清 0 会影响其他元素；用计数布隆或 Cuckoo Filter 替代。
- 追问：如何用 1 GB 内存对 10 亿个整数找出重复的？→ 答题要点：若范围是 32 位整数，Bitmap 需 512 MB，可行；若范围未知，用哈希分片到多个文件，逐片用 HashSet 检测。
- 追问：外部排序的瓶颈在哪？→ 答题要点：磁盘 IO 次数，优化方向是增大块大小（减少 run 数）、多路归并（减少轮数）、顺序读写（避免随机寻道）。

## 五、本章速记卡

- 大 O 是增长上界，丢常数与低阶项；均摊不依赖概率，平均依赖输入分布。
- `ArrayList.add` 均摊 O(1)：扩容总拷贝 < 2n；扩容 1.5 倍是为了复用释放的内存块。
- 数组赢在缓存行（64 字节）与预取；链表输在指针追逐与每节点约 40 字节开销。
- 两个栈实现队列：out 空时整批倒；两队列实现栈：push 时把老元素搬到新元素后面。
- 单调栈：求下一个更大 → 栈内递减，遇到大的弹栈结算；每个元素进出各一次，O(n)。
- 单调队列：存下标、值递减、队头即窗口最大值；两处淘汰（过期、非最优）。
- 哈希定位 `(n-1) & hash`，n 为 2 的幂；扰动 `h ^ (h >>> 16)` 让高位参与运算。
- 链表长度 ≥ 8 且容量 ≥ 64 才树化，退化阈值是 6；8 来自泊松分布（概率约千万分之一）。
- 二叉树迭代：中序"一路向左压栈，弹出访问，转向右"；Morris 用前驱空右指针做线索，O(1) 空间。
- 前序 + 中序可还原，前序 + 后序不可（单孩子无法定左右）。
- 红黑树：最长路径 ≤ 2×最短，插入最多 2 次旋转、删除最多 3 次；B+ 树为磁盘页设计，3 层可覆盖上亿行。
- 建堆 O(n)：底层节点多但下沉少，求和收敛到 2n；TopK 求最大用小顶堆。
- 拓扑排序：Kahn 靠入度，输出数 < 总数即有环；DFS 后序反转也可。
- 并查集 = 路径压缩 + 按秩合并，均摊 O(α(n)) ≈ O(1)。
- 比较排序下界 Ω(n log n)；Java 基本类型用双轴快排，对象用 TimSort（稳定）。
- 快排最坏 O(n²)（有序 + 固定 pivot）；三路划分解决重复元素，重复多时 O(n)。
- 二分统一左闭右开 `[lo, hi)`，`lo < hi`，`mid = lo + (hi-lo)/2`；二分答案要求判定单调。
- DP 三要素：状态定义、转移、初始化；0-1 背包容量倒序，完全背包正序。
- 海量数据两条路：近似结构（Bitmap / 布隆 / HLL）或分治（分片 + 归并）。
