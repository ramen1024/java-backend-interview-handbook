# Java 后端面试系统化复习手册

一套按"模块 → 考点 → 题目 → 追问"四层组织的面试复习资料。目标不是让你"看过"，而是让你在面试现场能把一道题从结论讲到原理、从原理讲到取舍。

全书 13 章、261 道题，正文约 55 万字（含代码、表格与图示），覆盖 Java 后端社招与校招的主流考察面。每章独立成篇，可单独复习，也可按目录顺序系统推进。

---

## 一、这套文档怎么用

### 1. 三层读法

| 阶段 | 读什么 | 目标 | 建议耗时 |
| --- | --- | --- | --- |
| 扫读 | 每章"考察重点概览 + 高频题清单" | 建立 Map，知道这一章有哪些题、哪些是 P0 | 每章 10 分钟 |
| 精读 | 每章"题目详解"的 P0/P1 题 | 能复述"一句话结论 + 三层原理 + 一个场景" | 每章 2~4 小时 |
| 自测 | 每章"速记卡 + 自测清单" | 合上文档能讲，讲不出再回读 | 每章 30 分钟 |

### 2. 每章的统一结构

- **一、本章考察重点概览**：面试官在这一章真正筛什么能力，附考点频率与难度表。
- **二、复习优先级**：P0 / P1 / P2 划分与时间分配建议，时间不够时按这个砍。
- **三、高频面试题清单**：题目 + 难度 + 优先级 + 一句话答案，可当索引使用。
- **四、题目详解**：每题固定五段式——一句话结论、先把话说白、底层原理、易混对比/代码、面试追问。
- **五、本章速记卡**：考前 10 分钟扫读。
- **六、本章自测清单**：以"能否不看文档讲出来"为标准自检。

### 3. 难度与优先级的含义

- 难度 `初级 / 中级 / 高级` 指**该题通常出现在什么级别的面试里**，不代表重要性。初级题答错，伤害远大于高级题答不出。
- 优先级 `P0 / P1 / P2` 指**投入产出比**。P0 是必须背到能画图的题，P1 要能说清主线，P2 是加分项。

## 三、模块权重与能力地图

面试的考察结构可以拆成三层。越往下越"通用"，越往上越"业务"：

```text
        ┌─────────────────────────────┐
  应用层 │ 系统设计 · 分布式 · MQ · Redis │  决定职级上限
        ├─────────────────────────────┤
  框架层 │ Spring · MyBatis · 微服务     │  决定能否快速上手
        ├─────────────────────────────┤
  底座层 │ Java 基础 · 集合 · 并发 · JVM  │  决定技术底色
        ├─────────────────────────────┤
  公共课 │ 网络 · 操作系统 · MySQL · 算法 │  决定排查与分析能力
        └─────────────────────────────┘
```

一个常见的误区是把时间全押在"框架层"。实际上：

- **初级岗（0~2 年）**：底座层 + MySQL 占 60%，框架会用即可，系统设计基本不问。
- **中级岗（3~5 年）**：底座层 30%、MySQL/Redis 30%、框架与分布式 30%、系统设计 10%。这一档开始区分"会用"和"懂原理"。
- **高级岗（5 年以上）**：系统设计与分布式占 40%，且每个方案都会被追问"为什么不用另一种""出问题怎么兜底"。底座知识不再是考点，而是你解释方案时的语言。

## 五、答题方法论

### 1. 五段式回答

任何一道原理题，都可以按这个顺序讲，长度控制在 60~90 秒：

1. **一句话结论**：先给判断，让面试官知道你没跑偏。
2. **是什么 / 怎么做**：用一句话定义，再给关键步骤。
3. **为什么这样设计**：讲约束与代价，这是区分度所在。
4. **边界与反例**：什么情况下不成立、什么场景不该用。
5. **落到场景**：我项目里是怎么用的、遇到过什么问题。

### 2. 对比题的答法

不要背"区别 1/2/3"，先给一个**判断维度**，再按维度展开：

> "这两个东西我会从三个维度看：一致性语义、失败时的行为、以及运维成本。先说一致性……"

维度选对了，答案自然有结构；维度选错，背得再多也像背书。

### 3. 不会的题怎么处理

- 不要编。先承认边界："这块我没有在生产上踩过，我按理解说一下思路。"
- 把问题拆成你会的部分："它本质上是一个 XX 问题，我能确定的是……"
- 给出验证路径："如果是我，我会先用 XX 命令看 XX 指标，再判断是 A 还是 B。"

面试官对"知道自己的边界 + 有排查思路"的评价，通常高于"硬编一个错误答案"。

### 4. 项目题的答法

用 STAR 但不背 STAR 的壳：

- **S（背景）**：一句话说清业务规模与约束（QPS、数据量、团队规模）。
- **T（你的任务）**：你负责的那一小块，不要说"我们团队"。
- **A（动作）**：至少包含一个**技术判断**和一个**被否决的方案**。"我们先考虑了 X，但因为 Y 放弃了，最后选了 Z。"
- **R（结果）**：给可验证的指标，没有指标就说清"上线后哪类问题消失了"。

## 六、使用建议

1. **先做题，再看答案。** 每章先扫"高频题清单"，对自己会的打勾、含糊的画圈、不会的画叉，只精读画圈和画叉的题，能省一半时间。
2. **用"讲给外行听"检验理解。** 如果一段原理你不能用三句话讲给非技术人员，说明你只是记住了词。
3. **每个模块准备一个故事。** 面试官问"你遇到过什么问题"时，有故事的人和没故事的人差距极大。建议：JVM 一个 GC 问题、MySQL 一个慢查询或死锁、Redis 一个缓存一致性或热 key、MQ 一个积压或重复消费。
4. **不要试图背完。** 这套文档的 P0 题目共 98 道，能把这 98 道讲到"结论 + 原理 + 取舍 + 场景"四层，已经超过大多数候选人。
5. **面试后立刻补记。** 被问住的题当天回填到对应章节的自测清单里，这是最高效的复习方式。

## 七、版本与口径说明

- Java 相关默认以 **JDK 8** 为基线，涉及新特性时标注 JDK 11 / 17 / 21 的差异。
- MySQL 默认 **InnoDB**，以 **5.7 / 8.0** 为主，涉及差异会明确标注。
- Redis 以 **6.x / 7.x** 为主，Kafka 以 **2.8+ / 3.x** 为主，Spring Boot 以 **2.x / 3.x** 为主。
- 文中涉及的默认值、阈值均标注了适用范围。不同版本、不同发行版可能存在差异，面试中表述为"通常/默认"比说死更安全。
